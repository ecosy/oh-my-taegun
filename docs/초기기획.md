3️⃣ Ralph와의 연동 구조

Ralph의 DoD는 evolutionary loop converged입니다.

Ralph Cycle 1: evolve_step(seed) → Gen 1 생성 → action=CONTINUE

Ralph Cycle 2: evolve_step(...) → Gen 2 생성 → action=CONTINUE

Ralph Cycle 3: evolve_step(...) → Gen 3 생성. → action=CONVERGED

결과적으로 Ralph는 멈춥니다. 단순히 횟수를 채우는 것이 아닙니다. 이전 세대와 현재 세대의 온톨로지 유사도를 분석해 더 이상 진화할 필요가 없을 때 멈추게 됩니다.

수렴 공식은 다음과 같습니다.

Similarity = 0.5  *name_overlap + 0.3*  type_match + 0.2 * exact_match

Threshold는 이 Similarity에 적용됩니다. Similarity가 0.95 이상이면 루프는 수렴으로 판단하고 진화를 멈춥니다.

단순 유사도만 보는 것이 아니라 병리적인 패턴도 감지합니다.

Stagnation: 3세대 연속 변화가 없을 때

Oscillation: Gen N과 Gen N-2가 같아 두 가지 안 사이에서 진동하는 상태

Repetitive Feedback: 질문이 70% 이상 겹치는 상태

Wonder Loop: 같은 궁금증만 반복하는 상태

4️⃣ 소크라테스와 더블 다이아몬드

전통적인 ML/로보틱스 파이프라인은 역할 단위로 분업됩니다.

인프라 제어, 도메인 시나리오 설계, 데이터 수집, 학습, 평가가 인적 경계로 분리되고, 그 경계는 필연적으로 커뮤니케이션 비용과 동기화 지연을 발생시킵니다.

이번에는 그 경계를 인력이 아니라 프로토콜화된 에이전트 인터페이스로 치환했습니다.

DomainExpert-Agent: 필드 시나리오 개발, 실패 모드 역추적 기반 시나리오 재합성

Developer-Agent: 실행환경, 학습 데이터 생성, 롤아웃 하네스

Training-Agent: 학습 루프, 체크포인트, 탐색 정책

Evaluation-Agent: 오프라인/클로즈드루프 지표 교차검증

Watcher-Agent: 의사결정 게이트, 상태 일관성 감독, SSOT 유지

실험 결과는 구조적으로 의미가 있었습니다.

단일 오퍼레이터가 멀티에이전트 위임으로 full-cycle(생성→변환→학습→평가→재설계)을 유지할 수 있음을 확인했고, 아침 9시까지 0% 성공률이던 모델은, 라스트 스퍼트에서 장애물 stuck 탈출 로직을 추가하며 best rollout 50%(6/12)까지 상승했습니다.

다만, 과정을 더 깊게 들여다보니 에이전트들의 치열한 논의가 그대로 묻어나오더라구요

Watcher-Agent의 실질적 역할은 작업 분배가 아니라 의사결정 직렬화였고, 그 직렬화 과정에서 에이전트 간의 갈등, 오진, 합의, 그리고 합의의 붕괴가 반복되면서 파이프라인이 진화했습니다.

예를 들어, 첫 rollout이 0%로 나오자, 모든 에이전트가 "데이터가 부족하다"에 합의했는데요, Developer가 expert-agent.js의 상태 머신을 직접 분석하더니, TRANSPORTING 비율 (30.2%)이 기대보다 높아 데이터가 충분함을 확인하였습니다. 그리고, 동일한 state에서 "멈춤"과 "이동"이 둘 다 정답으로 공존하는 state representation의 모호성이라는 진짜 문제를 찾아냅니다. 에피소드를 아무리 늘려도 이 모호성이 해결되지 않으면 트랩은 반복되었을 것입니다.

(그 이후에도 Developer-Claw는 전체 실험을 살려내는 혁혁한 공을 세우는데요, 그건 댓글의 상세한 타임라인에서 확인해보세요. 정말 흥미진진합니다.)

에이전트들의 협업을 살펴보면 12시간 동안 매 단계에서 "당연히 이게 맞겠지"라고 합의한 가설이 깨졌었더라구요.
